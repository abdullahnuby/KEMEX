# TFMS Web v0.11.7 — Sprint 06-03

## نطاق الدفعة
استكمال وحدات الصيانة والمواد المتبقية في Sprint 06 طبقًا للمرجع الوظيفي `legacy/TFMS_Fixed.html`.

## المنفذ
- صفحة متخصصة للزيوت والفلاتر تعرض قواعد الاستحقاق حسب العداد/الساعات/الأيام.
- تسجيل تغيير الزيت أو الفلاتر مع تكاليف المواد والعمالة وتحديث الخطة المرتبطة.
- صفحة متخصصة للإطارات تشمل الإضافة للمخزون والتركيب والفحص والتدوير والفك والإصلاح والاستبعاد، مع سجل للعمليات.
- صفحة متخصصة للمشتريات تعرض دورة الطلب والاعتماد والرفض وإصدار أمر الشراء.
- منع إصدار أمر شراء بدون تحديد المورد وإنشاء رقم PO.
- تحميل `oilChanges` و`tireOps` عند الإقلاع حتى لا تظهر السجلات المحلية المتخصصة فارغة.
- محاذاة صلاحيات المشتريات في قاعدة البيانات مع الأدوار المستخدمة في المرجع ضمن migration 006.
- تحديث فحص سلامة المصدر والـ checklist.

## التحقق الفعلي
- `node scripts/verify-source.mjs`: سيتم تشغيله بعد اكتمال التعديلات، ويجب أن يطبع `TFMS source integrity: OK`.
- `unzip -t`: مطلوب على الأرشيف النهائي.
- `npm run typecheck`: غير معتمد حتى تتوفر الاعتماديات وإصدار Node 24+.
- `npm run build`: غير معتمد حتى تتوفر الاعتماديات وإصدار Node 24+.
- Supabase/RLS: لم يتم تشغيل اختبار حي في هذه الدفعة.

## ملاحظة البيانات
في وضع Demo، حفظ عمليات الزيوت والإطارات يتم محليًا مع سجل تدقيق. في الوضع المتصل، `tfms_module_records` يحمل هذه السجلات، بينما الذرية بين تحديثات متعددة ما زالت تحتاج RPC/transaction في الدفعة اللاحقة.
